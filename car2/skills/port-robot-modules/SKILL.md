# 机器人模块移植

将参考项目中需要的能力接入目标项目，交付能构建、有调用示例、说明单位及硬件配置边界的实现。保留目标项目已有的组织方式；空项目可以采用参考工程的目录布局。

## 定位参考项目和移植范围

本 Skill 提供移植方法与源码索引，不包含完整驱动源码或厂家库。

- 优先使用用户提供的参考项目、目标项目路径与模块范围。当前工作区通常是目标项目，不一定是参考项目。
- Skill 随仓库保存时，可向上查找同时具有 `CMakeLists.txt` 和 `src/thirdparty/` 的参考根目录；全局安装后不要把 Skill 目录当成源码目录。
- 缺少参考源码时，先检查目标项目，再询问源码所在路径。不要猜测开发机绝对路径，也不要自行获取未指定的同名仓库。
- 检查两边的 `AGENTS.md`、CMake、公开头文件和相关配置。本文中的路径相对参考根目录；当前源码优先于文档记录。

按实际需要选择范围（下表前三行路径位于 `src/thirdparty/`）：

| 需求 | 起点 | 重点 |
| --- | --- | --- |
| 只要机械臂正逆解 | `arm/kinematics.h/.cpp` | 纯 C++17，长度、零偏、限位由目标项目提供 |
| 只控制一种电机 | 对应 `motor/<品牌>/` | 同时带齐通信与协议依赖；选择目标项目的 transport |
| 机械臂或底盘硬件控制 | `arm/control.*` 或 `chassis/control.*` | 保留周期更新、共享电源和退出顺序 |
| 完整 ROS 2 主控 | 上述模块及 `src/example/` | 接入话题、参数、默认配置和应用生命周期 |

查依赖、单位及真实 API 时读 [项目模块地图](references/project-map.md)。决定构建方式、配置迁移与验收方法时读 [移植指南](references/porting-guide.md) 中对应范围。

## 实施方式

1. 用简短说明列出选定模块、源文件到目标路径的对应、依赖以及保留的 ROS 接口。范围已明确时直接实施，不增加确认环节。
2. 从现有 CMake 的源文件清单和公开头文件递归确认依赖。只迁移所需模块及其依赖；遇到已有库、总线或主循环时优先接入它们。
3. 保持职责边界：`communication.h/.cpp` 处理协议及收发，`motor.h/.cpp` 提供设备实际支持的使能、失能、模式和目标输入；机械臂、底盘负责领域控制；应用负责调度、ROS 和共享资源。
4. 按目标硬件改配置与构建路径，接入目标项目已有的错误处理。保留 Result/异常语义，不把发送成功表述成电机已经到位。
5. 提供能直接复制调用的短示例，注明输入、输出、单位、初始化及周期调用位置。沿用用户指定的函数片段或独立程序形式；阅读用例子默认不加入构建。
6. 做与移植范围匹配的离线验证，交付改动位置、调用方式、验证结果和仍需实机配置的项目。构建产物放目标项目既有构建目录或工作区外的临时目录。

不要把整个旧工程嵌入目标项目来解决单个头文件缺失。不要携带 `build/`、`install/`、`log/`、`.omx/`、旧调试产物或开发机服务配置。

## 必须保留的行为边界

- 底层模块不依赖 ROS，不代表原根 CMake 可以脱离 ROS 构建。无 ROS 移植要提取所需源码并写对应的小型 CMake；完整 `find_package(chassis)` 仍有 ROS 依赖。
- 同一总线共享 transport/master；通信对象比电机对象长寿，接收回调由所属主站统一管理。应用按先停车/失能、再停止通信、最后关闭共享电源的顺序退出。
- BXI MIT、ISWV CANopen、意优 EtherCAT 支持的模式和单位不同，不强行包装成语义相同的模式。模式切换、当前位置保持和掉线处理沿用实际驱动契约。
- 硬件通道、网卡、站位、方向、编码器、减速比、零偏、限位与启动回零必须按新设备核对；未知值列为待配置项，不把示例值当作已校准结果。
- 移植和离线验证不包含上电、运动、写 EEPROM、设置零点、重配网卡或启用系统服务。用户另行要求实机工作时，只执行已明确授权的范围；不要运行硬件调用例子来验证编译结果。
- 保留随所选源码和厂家库提供的许可、来源及本地补丁记录；参考 `docs/dependencies.md`，不要把根许可证套用到所有供应商文件。
