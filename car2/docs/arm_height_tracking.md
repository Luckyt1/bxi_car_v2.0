# 记录三维目标并控制机械臂前伸

机器人开机无窗口视觉服务使用 **APPROACH**。按 button6 后，先利用连续有效深度帧让
底盘消除横向 Y 偏差，此时机械臂 X/Z 保持。横向误差进入 ±2 mm 后，横移归零；
保持对齐至少 0.3 秒，再从此后新采集的一帧记录目标的肩坐标。
终点高度为**两个标记三维中点下方 0.0745 m，X 停在目标平面前 0.04 m**，pitch 保持启用时的值。
按当前水平相机安装，前伸距离为 `max(0, 深度 − 0.04 m)`，例如深度 20 cm 时前伸 16 cm。
距离不足 4 cm 时保持记录时的 X，Z 仍到偏移高度。

记录成功后，底盘停止横移，机械臂将完整固定 X/Z 终点一次交给电机 PP 控制，前伸、调高。
此后标记太近出画、遮挡或没有有效深度，都不会丢弃已记录的目标；新看到的目标也
不会改变本轮终点。X/Z 合成误差不超过 2 mm、目标俯仰误差不超过 0.01 rad 后停止并保持，不会自动抓取或重新寻找
下一个目标。需要新终点时，按 button6 退出，再按一次重新记录。
目标位置是在记录瞬间确定的；目标之后移动时，本轮仍去原位置。

保存目标之前没有 10 秒超时，未识别到时继续等待，重新获得连续有效帧即可继续。
保存后若末端反馈失效、执行指令断流、机械臂失败或用户退出，本轮目标作废，须关闭
再开启；有效图像恢复不会复活已取消的动作。相机采集进程故障仍会停止执行。

其他模式保留：脚本默认 `pixel` 只开彩色流，固定 X，由机械臂上下与底盘左右将中点
对准画面中心；`pixel-depth` 在此基础上保持本轮首组稳定帧的相机深度；`depth` 跟踪
中点下方 0.0745 m 的 Z 和横向 Y，固定 X。这些实时模式丢失目标会暂停，恢复后重获。
视觉不请求底盘前进、后退或旋转。

`approach` 显式使用 640×360@30 的深度流，彩色流默认仍为 640×480@30，深度经 SDK
对齐到彩色图后使用实际内参。原 SDK 自动选择的 848×480 深度档最小测距约 18 cm，
640×360 档约 14 cm，详见[厂家数据表的 Minimum-Z Depth](https://www.orbbec.com/wp-content/uploads/2025/06/Gemini-330-series-Datasheet-V1.6.pdf)。
2026-10-25 现场目标约 16～19 cm 时，旧档 45 帧中 43 帧深度样本不足，导致横移
断续且无法记录终点。指定近距离档不可用时直接报错，不静默退回原档。
二维码识别成功不等于已有可靠深度；保存终点前仍要求深度有效、连续稳定，
`insufficient_depth_samples` 和 `depth_discontinuity` 不会被当作可执行坐标。

## 相机安装参数

`src/config/arm_tracking.json` 按用户于 2026-10-21 确认的安装关系填写：
相机随末端运动，彩色镜头中心在末端中心正上方 62.5 mm，无其他平移；
镜头正朝末端前方，画面上方与末端上方一致。

`rotation` 将相机光学坐标（X 右、Y 下、Z 前）映射到末端坐标
（X 前、Y 左、Z 上），`translation_m=[0,0,0.0625]`。
`depth` 与 `approach` 再用 `/arm_pose` 的实际位姿转入肩坐标，最后减肩坐标 Z 的 0.0745 m。
偏移在转入肩坐标后施加，因此机械臂俯仰变化不会把“向下”变成相机向下。
`approach_standoff_m=0.04` 仅在 `approach` 记录终点时，从肩坐标 X 扣一次，
并限制终点 X 不小于记录时的实际 X；它不改变 Z，也不影响其他跟踪模式。
相机有俯仰时，先按外参和实际姿态投影到肩坐标，再扣 X 的 4 cm，
此时 X 前伸量不等于原始光学深度直接减 4 cm。旧配置省略该项或设为 0 时保持原终点。
该外参来自上述安装尺寸确认，尚未经过实机测距与手眼标定精度验收。
末端中心必须对应当前 FK 的工具点；若修改工具长度或相机安装位置，应重新校准配置。

肩 +Z 按现有机械臂坐标定义是机器人向上，不包含车体倾斜后的重力方向补偿。
`calibrated=false`、缺失平移、非刚体旋转和非法数值都会阻止执行模式。
`fixed` 模式的外参直接映射到肩坐标；当前实机配置使用 `tool`。
像素模式只接受上述朝前、画面上方对应工具上方的 `tool` 安装关系；
画面向上在肩 +Z 的投影小于 cos(30°) 时返回 `pixel_camera_not_upright`，
防止大俯仰时沿错误方向纠偏。按当前配置即要求末端俯仰在约 ±30° 内。

## 启动

机器人开机由 `car2-arm-tracking.service` 启动相机，无需登录桌面，也不弹出预览窗口。
服务源文件为 `deploy/car2-arm-tracking.service`，使用 `--headless --joystick` 待机，
button6 才请求跟踪；进程异常退出后自动重启，并要求新的关闭→开启按键请求。
原 `~/.config/autostart/car2-arm-tracking.desktop` 已禁用，模板同样标记为禁用，避免重复打开相机。
button6 负责切换已运行的视觉程序，不能单独启动相机。

部署或更新服务：

```bash
sudo install -m 644 deploy/car2-arm-tracking.service /etc/systemd/system/car2-arm-tracking.service
install -m 644 deploy/car2-arm-tracking.desktop ~/.config/autostart/car2-arm-tracking.desktop
sudo systemctl daemon-reload
sudo systemctl enable --now car2-arm-tracking.service
```

需要桌面预览时，先停止后台相机服务，再在已登录桌面的终端运行：

```bash
cd /opt/bxi_car/car2
sudo systemctl stop car2-arm-tracking.service
bash start_arm_tracking.sh --joystick --tracking-mode approach
# 像素对中，同时保持开启时的相机深度：
bash start_arm_tracking.sh --joystick --tracking-mode pixel-depth
# 仅像素对中，固定 X：
bash start_arm_tracking.sh --joystick --tracking-mode pixel
# 显式使用原三维目标（需要有效深度）：
bash start_arm_tracking.sh --joystick --tracking-mode depth
```

退出手动预览后，用 `sudo systemctl start car2-arm-tracking.service` 恢复无窗口待机。

视觉日志可用 `journalctl -u car2-arm-tracking.service -b -n 30` 查看。
若重启后按 button6 没有动作，先确认 `systemctl status car2-arm-tracking.service` 显示运行，
再检查日志中的目标识别和跟踪状态；只有手柄请求、没有视觉进程时，不会产生机械臂目标。

手动预览窗口显示 `READY APPROACH` 时只识别、等待按键。开启后显示 `aligning`、`settling`、
`approaching`，到位显示 `goal_reached`；异常取消后须切换模式重新开启。
日志 `tracking.phase` 记录阶段，`goal_m` 和 `goal_capture_timestamp_ms` 记录本轮终点
及原始图像时间。日志 `tracking.tracking_mode` 为 `pixel`、`pixel-depth`、`depth` 或
`approach`，`tracking.mode` 另表示
`standby`、`execute` 或 `preview`。整车控制服务必须已加载新版程序；
它先等待 button14，按下后才执行原有机械臂回零与底盘校准。启动完成且手柄
回中后，按一下 **button6** 请求进入跟踪，再按一下退出并保持相机采集。
等待启动或校准期间按 button6 会被丢弃，不会在校准结束后自动进入。

窗口阶段是视觉端状态，尚未接收控制器的执行确认。若控制器因不可达、指令过期或
驱动故障拒绝执行，窗口可能仍显示 `approaching`；以整车日志中的
`ARM_TRACKING goal rejected` / `ARM_TRACKING hold` 原因为准，退出再开启才可重试。

按 button6 开始前，底盘前后、左右和旋转杆必须回中；杆偏转时的开启请求会被丢弃。
跟踪期间推动任一底盘杆会取消跟踪。控制器退出视觉模式并完成交接后，
需收到回中零速才能重新接受手动移动；回中不会自动重新进入跟踪。
记录前需要连续有效标记及新鲜末端反馈，记录后执行只依赖固定终点和新鲜反馈。
button11 保持原急停操作；
`q`、Esc、关闭窗口或 Ctrl-C 停止并关闭视觉进程。使用 button6 时不必再加
`--execute`，两种启动方式不能同时使用。

button6 按住不会反复切换，启动/重连时按住也不会进入。手柄失联、输入失效、
stop/enable 不许可会取消请求；视觉端超过 300 ms 未收到手柄状态也会退出。
恢复后需要新的关闭→开启请求，不会自动继续。若视觉进程在手柄请求为开启时
重启，先按 button6 关闭请求，再按一次开启。切换期间的退出事件优先处理。
窗口若显示 `disable_pending`，表示已停止发目标、等待控制器确认退出；
此时保持预览并重试退出，确认前禁止再次进入。

当前服务使用 `/dev/input/jsBattleDragon`；设备缺失时先连接实际手柄，不要把
鼠标或其他虚拟 `/dev/input/js0` 当作手柄使用。

先关闭已有相机预览，避免两个程序占用同一设备。默认只显示计算结果：

```bash
bash start_arm_tracking.sh
# 无桌面检查有限帧，不发控制指令：
bash start_arm_tracking.sh --headless --max-frames 150
```

执行模式需要新编译的整车控制器已运行、完成原有启动流程，且能收到新鲜
`/arm_pose` 和持续的 `/cmd_vel_car` 手柄心跳（回中零速也算心跳）。
未收到心跳或超过 `command_timeout_sec`（默认 300 ms）会锁止本轮跟踪；
恢复心跳后需关闭再开启跟踪。该要求也适用于 `--execute`。启动动作必须显式指定：

```bash
bash start_arm_tracking.sh --execute
```

脚本默认使用和 `deploy/ros_elf_launch.service` 相同的 ROS 域 89、CycloneDDS
和 loopback 网络配置；显式设置的 ROS 环境变量优先。原来的
`start_qr_midpoint.sh` 仍然只识别，不控制机械臂。

`q`、Esc、关闭窗口或 Ctrl-C 会发送停止并关闭跟踪模式；默认预览不会创建
控制发布器或参数客户端。命令行支持原来的 ArUco ID、相机序列号、分辨率、
深度、JSONL 和离线图片参数；`--execute` 和 `--joystick` 都禁止图片模式。
`pixel` 自动使用仅彩色模式；`pixel-depth`、`depth` 和 `approach` 控制禁止 `--color-only`。

## 控制行为

- `arm_tracking_enabled` 默认 false，拒绝 true 的启动覆盖值；只有运行时显式启用。
- 启用先取消前三轴原目标并减速，停稳后锁定 pitch 和起始 Z；未启用 X 控制时还锁定实际 X。
- `approach` 原子启用 `arm_tracking_enabled`、`arm_tracking_x_enabled`、`arm_tracking_goal_enabled`，退出时同时关闭。`pixel-depth` 只启用前两个。新增开关默认 false，禁止启动时设为 true，运行中的会话不能直接切换控制方式。
- `approach` 的最终采集必须晚于运行时启用事件，以及横移归零后的 0.3 秒稳定期；SDK 缓冲旧帧不能充当新采集。接收端等待机械臂停稳取得基准后，对完整终点做 IK、关节限位和起始 Z ±150 mm 检查；不通过则本轮取消，不先向不可达终点试探移动。
- `approach` 提交固定目标后忽略所有实时图像目标包，Y 永远为零。固定目标续发必须保持相同 X/Z；坐标变化、过期、停止、执行失败或完成都会锁存本轮，关闭再开启才能接收新目标。
- 视觉端在采集阶段要求至少 3 个连续、唯一且有效的帧。`pixel` 检查标记中点、图像大小及新鲜实测位姿；其他模式还要求有效且同步对齐的深度。实时跟踪或固定目标采集阶段丢失目标、脏像素或大幅跳变立即停止输出有效目标。
- 像素参考为 `((图像宽度 - 1) / 2, (图像高度 - 1) / 2)`，左右和上下各自 8 px 内不纠偏；外侧采用 0.1 mm/px 的目标纠偏增益，至少 3 mm、最多 10 mm。3 mm 用于越过控制器的 2 mm 死区；完整高度目标经 IK 校验后直接下发。这是反馈增益，不是像素到真实距离的标定。
- 底盘横移使用 `vy = clamp(2 × 横向误差, -0.020, +0.020) m/s`，横向误差绝对值不超过 2 mm 时为零；按约定 +Y 为向左。视觉拥有底盘期间，前后和旋转命令为零。手柄回中零速心跳不覆盖视觉横移；非零手动指令会锁止本轮跟踪。退出时清除视觉速度并等待回中，再交还手动控制。
- 正常跟踪没有累计横移时长上限，持续到 button6 关闭模式或手动接管。实时模式丢失目标、过期时暂停，重新获得有效目标后可恢复；`approach` 保存终点后的丢图不影响执行，但执行故障不自动恢复。
- `pixel-depth` 的 X 使用两标记三维中点的光轴深度，偏差按相机光轴在肩 +X 的投影换算为前后纠偏；超过 5 mm 死区时，每次目标纠偏最多 10 mm，完整 X/Z 目标经 IK 和关节限位校验后下发。日志包含 `depth_m`、`depth_reference_m`、`depth_error_m`、`x_correction_m`。深度突然变化超过配置的 50 mm 时重新等待 3 帧稳定结果，保持本轮参考距离。
- 像素中点一帧跳变超过 80 px、图像尺寸变化，或肩坐标目标跳变超过配置的 50 mm，都需要重新获得 3 帧稳定结果。日志 `pixel_error_x` 正数表示目标在参考线左侧，`pixel_error_y` 正数表示在上方；`y_correction_m`、`z_correction_m` 是两方向目标纠偏量。
- 采集阶段每帧和执行阶段末端反馈最多允许 250 ms 年龄。实时目标时间戳表示图像采集时间；固定目标使用独立话题，其时间戳表示当前执行指令生成时间，原始图像时间保留在日志中。接收端检查指令年龄 250 ms、严格递增时间戳和 300 ms 接收期限，在推进电机握手前检查失效；不能靠缓存目标恢复已取消的会话。
- 接收端只在启停、显式 stop 或已有目标转入保持时建立新的采集时间门槛；保持期间重复收到无效帧不会不断后移门槛。`target rejected` 日志区分具体原因并打印 `age_ms`、`after_hold_ms`、`after_last_ms`，所有拒绝日志共享 1 s 限流，避免有效但有处理延迟的图像永远无法恢复。
- 视觉接收端直接提交完整目标，速度和加减速使用 `yiyou_arm_speed_rpm`、`yiyou_arm_acceleration_rpm_s`；不再另设末端速度预算、毫米级分段或每步 1° 关节增量限制。目标高度仍限制在启用高度 ±150 mm；未开启 X 时保持启用时的 X，目标 pitch 保持启用时的值。最终完成要求完整 X/Z 误差不超过 2 mm、pitch 误差不超过 0.01 rad，避免肩肘到位时提前停止尚未到位的腕轴。
- 实时模式只等待驱动器 PP 指令握手，不等待上一目标实际到位。握手期间只保留最新观测，完成后提交最新的不同目标；相同坐标只续期，不重复触发电机。`approach` 的固定终点只提交一次，后续心跳只续期。
- 完整终点仍必须通过 IK、肘分支和关节绝对限位检查；不可达目标直接停止，不缩成局部可达目标。实时目标反向时先取消旧指令、等待停稳，再接受新帧。
- 已取消分段到位等待和原有 2 s 小步到位超时。PP 握手超时、驱动故障、反馈失效和命令断流仍停止执行；握手成功且心跳、反馈持续正常时，没有额外的机械运动进度超时。
- 仍走原有 IK、肘分支、关节限位和目标回读校验。指令接受与实际到位是两个状态。
- 失效时取消未发及已接受的前三轴目标，保持使能并减速停止，同时横移命令归零。目标过期、显式 stop 或机械臂不可达均停止横移；手柄速度心跳断流也锁止跟踪。驱动器故障仍沿用原来的故障锁存和共享电源断电。
- 视觉模式和交接期间拒绝手柄对前三轴目标的参数写入。关闭模式并停稳后，把手动目标同步到实际位姿，避免重放保存的旧目标。
- button6 请求开启期间，手柄端暂停前三轴点动；退出后 axis7 需回中才能恢复点动。底盘由视觉接管，第四轴仍保留原有手动操作。

手柄第四轴保留原有操作方式；跟踪时不要同时操作手柄末端点动。
原手柄 GET/SET 参数协议没有会话代次，极短启停期间在网络中延迟的旧手动
请求无法和新请求严格区分；开始与结束跟踪前应保持末端点动键释放。

固定 pitch（未启用深度 X 时还固定 X）是目标约束。底层是三轴独立 PP 点到点，不是同步的笛卡尔直线
轨迹，因此不能承诺运动途中未调节轴完全不偏移，也不提供碰撞规划。
完整终点的可达性校验不代表中间路径已验证；实际运动速度由各轴驱动器 PP
速度和加减速设置决定，编码器换算另有离散分辨率。

## 接口与验证

视觉接收 `/arm_pose`；执行时发送：

| 接口 | 内容 |
| --- | --- |
| `/arm_tracking_target` | `geometry_msgs/PointStamped`，肩坐标目标；pixel 的 Y/Z 为像素纠偏；pixel-depth 另含实测 X 加深度纠偏；depth 为变换后减去竖直偏移；Y 控制底盘横移，X/Z 控制机械臂 |
| `/arm_tracking_goal_target` | `geometry_msgs/PointStamped`，approach 固定肩坐标终点，Y=0；时间戳为当前执行命令时间，持续续发维持通信心跳，不能更换坐标 |
| `/arm_tracking_stop` | `std_msgs/Empty`，取消视觉目标、横移归零并保持机械臂 |
| `/arm_tracking_requested` | `std_msgs/Bool`，手柄每 50 ms 刷新的模式请求；只有 `--joystick` 入口接收 |
| `/chassis` 的 `arm_tracking_enabled` | 显式启用／关闭视觉所有权 |
| `/chassis` 的 `arm_tracking_x_enabled` | 本轮会话是否执行目标 X；只在关闭时配置或随模式原子启停 |
| `/chassis` 的 `arm_tracking_goal_enabled` | 本轮是否先横向对齐、再执行固定终点；要求 X 开启，只在关闭时配置或随模式原子启停 |

启动流程在按 button14 后会执行回零和底盘校准，不能把启动键当作普通预览操作。
