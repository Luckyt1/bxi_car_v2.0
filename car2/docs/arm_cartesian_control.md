# 意优前三轴：仿真零位与 ROS 末端目标

`chassis`、`key_control`、`robot_control` 的机械臂控制器已接入与 MuJoCo
仿真相同的平面 2+1 正逆解。`chassis_only` 系列不创建机械臂接口。
前三个 EtherCAT 站位依次为肩、肘、腕，第四轴独立使用 PP 位置点动。

## 零位与坐标

- 肩轴心为原点，X 向前、Z 向上，长度单位为米。
- pitch 为平面仰角，单位为弧度，正方向从 +X 转向 +Z（绕 -Y）。
- 连杆默认 0.30 m / 0.40 m，工具偏移 0 m。
- 关节角 q 相对标定零位；几何相对角为 q 加 `[150°,-150°,0°]`。
- q 全为 0 时，上臂朝后上方 150°，前臂和工具朝前水平。
  此时末端约为 `[0.1401923789,0.15,0.0]`。
- 肩、肘、腕标定角限位分别为 `[-150°,30°]`、`[-30°,330°]`、`[-180°,180°]`。

电机映射使用
`q = direction * (encoder_counts - zero_counts) * 2π / pulses_per_output_revolution`。
每个电机的编码器分辨率和减速比由驱动器反馈读取。几何 150° 偏置只参与解算，
不会额外写入电机目标。当前 `src/config/yiyou_ethercat.yaml` 的三轴方向为
`[1,-1,1]`：第二关节反向，第一、三关节正向；运行时以实际加载的方向参数为准。
零点计数仍均为 0；正解反馈和逆解下发使用同一方向映射。未加载 YAML 时，
程序方向参数默认仍为 `[1,1,1]`，应通过参数覆盖实机安装方向。

主程序启动先保持实测位置，再默认以 PP 模式回到已保存的三轴零位
（`yiyou_arm_zero_counts`，即 q=[0,0,0]），不重新设零或写 EEPROM。
`key_control` / `robot_control` 仍须先按 button14；回零完成后才校准底盘并开放遥控。
回零按各关节限速执行，不保证末端直线轨迹；最多等待 300 s，期间仍处理 button11 急停。
三轴必须完成本次 PP 握手、报告到位、位置误差不超过 100 脉冲且报告静止，才算回零完成。
日志依次为 `ARM_HOME_START`、`ARM_HOME_DONE`，底盘校准后显示 `EtherCAT arm IK ready`。
当前测量角或零位超限、单轴回零超过 180°、超时或通信故障会中止启动并请求共享电源断电。
设置 `yiyou_arm_home_on_start:=false` 可恢复启动原位保持；此时仍拒绝超限的末端请求。

## ROS 接口

主程序完成校准、日志显示 `EtherCAT arm IK ready` 后，设置同一数组参数：

```bash
# 请求运动：肩坐标系 x=0.15 m、z=0.15 m、pitch=0 rad。
ros2 param set /chassis yiyou_arm_target '[0.15, 0.15, 0.0]'
ros2 param get /chassis yiyou_arm_target
ros2 topic echo /arm_pose --once
```

三个元素必须都是浮点数。启动时该参数为空数组；拒绝非空启动覆盖值，
避免启动后意外追逐一个预设目标。参数回调只验证，已提交的新值在控制定时器中排队，
随后逐周期下发。包含其他非法参数的原子请求不会向电机下发目标。
重复设置相同目标不会重复触发运动。参数是请求值，不是运动完成反馈；
实际位置以 `/arm_pose` 和 `ETHERCAT_YIYOU_POSE` 日志为准。

`/arm_pose` 类型为 `geometry_msgs/msg/PoseStamped`，frame 为 `arm_shoulder`，
position.y 固定为 0；四元数为 `(x=0,y=-sin(pitch/2),z=0,w=cos(pitch/2))`。
它使用 ROS 四元数约定，所以 ROS RPY pitch 的符号与输入的平面仰角相反。

旧 `can3_motor_*_angle_deg` 保持只读；遥控器已移除选关节、写单关节角度的逻辑。

## 手柄末端点动

`key_control` / `robot_control` 完成启动校准后，沿用原机械臂按键：

| 操作 | 行为 |
| --- | --- |
| button1 | 选择下一项：x → z → pitch → x |
| button3 | 选择上一项：x → pitch → z → x |
| axis7 负方向 | 所选坐标增加一步 |
| axis7 正方向 | 所选坐标减少一步 |

默认选 x，x/z 每步 0.01 m（1 cm），pitch 每步 π/180 rad（1°）。
x 增加表示向前，z 增加表示向上，pitch 增加表示抬头；实际电机方向仍由标定映射决定。
短拨立即走一步；保持 axis7 同一方向时，每 0.1 s 触发一步，回中停止追加。
100 ms 重复使用单调时钟，由控制周期调度，繁忙或延迟时跳过、不补发积压步进。
切换坐标或不经过回中的直接反向会暂停连发，必须先回中再拨动；选项按钮每次松开再按才切换。
轴 0/3/6 继续控制底盘，button14 启动、button11 急停行为不变。
日志 `ARM_SELECTED coordinate=...` 显示当前选项，`ARM_REMOTE` 显示请求结果。

每一步先读取 `yiyou_arm_target`；首次为空时从 `/arm_pose` 的实际位姿起步，
之后基于主节点当前保存的目标做增量，并提交完整数组，走同一套 IK 和限位检查。
必须收到 `arm_shoulder` 坐标系的有效平面位姿，且最近一次接收距当前小于 500 ms。
回读参数后、提交前还会再次检查反馈新鲜度；没有反馈时不会拿默认零坐标运动。
请求异步执行，最多一个在途请求。请求忙或三轴握手忙时跳过本次长按步进，不排队；
服务超时 2 s、反馈无效、服务不可用或目标非法时暂停长按，回中后才能再次触发。
启动/校准期间不接受点动。重连需要回中和释放选择键；取消或切换坐标不会重放未提交的请求。
回中会取消尚未提交的长按重复请求，短拨的首步仍可完成提交。
button0/使能释放会取消未提交步进，但已提交的点到点目标可能继续运动；button11 才是急停。
其他 ROS 发布端也能设置目标，应避免同时操作手柄和外部目标写入端。

以下为 `remote_ctrl` 的启动参数，不改变主程序电机速度：

| 参数 | 默认值 |
| --- | --- |
| `arm_node` | `/chassis` |
| `arm_pose_topic` | `/arm_pose` |
| `arm_translation_step_m` | `0.01` |
| `arm_pitch_step_rad` | `0.017453292519943295` |
| `invert_arm_direction` | `false`（设为 true 反转 axis7 步进方向） |

旧遥控节点参数 `can3_node` / `invert_can3_direction` 已替换为上述参数。
完整机器人入口为 `src/example/main.cpp`，部署命令见根目录 `README.md`。
点动参数通过 ROS 启动参数传入，例如 `--ros-args -p arm_translation_step_m:=0.01`。
电机点动与零位标定使用根目录 `start_yiyou_jog.sh`，其维护实现位于 `tools/`；
离线机械臂解算和底盘调试可使用 `python3 test/debug.py`。

## 配置

下面参数都只允许在启动时设置，示例见 `src/config/yiyou_ethercat.yaml`。

| 参数 | 程序默认值（未加载 YAML） | 含义 |
| --- | --- | --- |
| `yiyou_arm_motor_directions` | `[1,1,1]` | 各轴电机正转到仿真正角的符号，只允许 ±1 |
| `yiyou_arm_zero_counts` | `[0,0,0]` | 仿真 q=0 对应的各轴绝对编码器计数 |
| `yiyou_arm_speed_rpm` | `0.6` | PP 输出轴速度，约 3.6°/s；回零和末端控制共用 |
| `yiyou_arm_acceleration_rpm_s` | `1.0` | PP 输出轴加减速度 |
| `yiyou_arm_home_on_start` | `true` | 主程序初始化后返回已保存的三轴零位；false 为原位保持 |
| `yiyou_arm_kinematics_file` | 空字符串 | 默认内置仿真几何，可指定 `arm_kinematics.json` 或仿真 `arm.json` |

`joint_limits` 字段。长度为米，偏置和限位为弧度；旧格式缺省 `zero_offsets`
时按 `[0,0,0]` 处理。更改仿真配置后应同步给控制器；本包中的配置是集成时的副本。

## 运动与故障边界

逆解用上一已接受的关节目标作种子，保留启动肘分支，按几何肘角判断正负，
不自动翻肘。不可达、非有限值、关节超限、编码器目标溢出、奇异目标以及
任一关节需跨越超过 180° 的请求都会被拒绝，保留原目标。

三轴目标先全部校验，再逐轴写入并读回，全部成功后才触发运动。运行期握手
逐周期推进，无等待应答的 sleep 循环；目标 PDO 下发最多等待 10 ms 确认，
允许短暂丢帧后在后续周期确认；每周期最多一次目标 SDO 读回，显式超时 5 ms，
整组握手期限 1 s。握手期间新目标会被拒绝。握手/I/O/反馈故障会锁存，
请求关闭共享电源并停止所有轴；不会自动重试或恢复。顺序触发期间仍可能部分轴已接受目标，
因此通信失败采用整组断电处理。

三轴分别按驱动器 PP 速度和加减速度运动，这是关节点到点控制；不保证
三轴严格同步、末端直线轨迹或避碰。应答完成只表示目标已接受，不代表运动到位。
普通 Linux 调度、PDO 等待和错误清理也不提供硬实时保证。
这些软件行为有离线测试覆盖，实机标定、运动方向和机械响应尚未验证。

## EtherCAT 通信耗时日志

进入 EtherCAT 周期通信后，`EtherCAT timing config:` 打印当前时序参数；
`EtherCAT timing: reason=periodic` 每 5 秒汇总实际平均耗时和最大耗时，单位均为微秒
（1000 us = 1 ms）。通信周期为 2 ms，收包/单站状态查询超时为 1 ms。
`EtherCAT protection config:` 会打印当前连续失败阈值。

| 运行期情况 | 判断与处理 |
| --- | --- |
| PDO 工作计数不正确或没有回包 | 前两次保留上一份有效反馈；连续第 3 次失败锁存故障并断电 |
| 单个从站 AL 状态查询超时 | 按从站分别计数；下一周期复查失败从站，连续第 3 次查询失败锁存故障 |
| 收到明确非 OP 状态、AL 错误位或非零 AL 错误码 | 立即锁存故障 |
| 距上一份有效反馈超过 20 ms | 立即故障；循环开始和发布新反馈前均检查，迟来的正常帧不能覆盖已经超期的事实 |
| 超速、急停、目标确认超时或其他电机故障 | 仍走原有保护流程 |

PDO 和各从站 AL 分别在成功回复时清零连续失败次数。无效 PDO 不能更新缓存输入、
反馈新鲜度或命令送达确认；已经锁存的故障不能因后续回包恢复而自动解除。
3 次是连续次数阈值，实际时间受调度和调用耗时影响，不代表保证在 6 ms 内响应。
这些初始阈值用于容忍短暂通信异常，仍需结合实机计时记录判断实际链路情况。

```bash
journalctl -u ros_elf_launch.service -b -f -o short-iso | grep --line-buffered 'EtherCAT timing\|EtherCAT fault'
```

| 字段 | 含义 |
| --- | --- |
| `interval_us` / `wake_late_us` | 相邻循环开始的实际间隔 / 相对计划唤醒时间的迟到量 |
| `lock_wait_us` | 本轮两次获取过程映像锁的等待时间之和 |
| `send_us` / `receive_us` | 发送函数 / 接收函数的实际调用耗时 |
| `al_total_us` / `al_max_us` / `al_max_slave` | 本轮全部状态查询耗时 / 最慢单次查询耗时 / 对应从站 |
| `work_us` / `overrun_us` | 本轮从开始到休眠前采样点的耗时 / 超过下一计划周期的时间 |
| `feedback_age_us` | 发布本轮反馈前，距上一次成功接收并发布反馈的时间 |
| `wkc` / `expected_wkc` | 本轮实际 / 期望工作计数；汇总行用 `last_wkc` 表示最后一轮 |
| `skipped_samples_total` | 日志线程短暂占用采样缓冲区时被跳过的累计样本数 |
| `pdo_failure_streak` / `al_failure_streak` | 当前 PDO 连续失败次数 / 本轮失败从站中最大的连续查询失败次数 |
| `al_failed_slave` | 上述 AL 连续失败次数对应的从站 |
| `pdo_invalid_cycles` / `pdo_recoveries` | 汇总窗口中的 PDO 异常周期数 / 恢复次数 |
| `al_timeouts` / `al_recoveries` | AL 查询超时次数 / 恢复次数（汇总行是窗口总计，明细行是本轮值） |

这些是单调时钟测得的主机侧耗时，包含调度抢占和驱动等待，不能直接当成网线传输延迟。
统计行的 `_avg` / `_max` 分别为窗口内平均值 / 最大值；第一轮没有间隔，
不计入 `interval_us_avg`。AL 平均值按所有采样周期计算，未查询的周期计 0；
排查单站查询超时时主要看 `al_max_us_max` 和 `al_max_slave`。
出现尚未达到故障阈值的异常时，同一汇总窗口另外输出一条 `EtherCAT timing warning:`，
保存窗口中最后一次异常的明细，即使之后恢复也能看到；不会每个周期同步打印告警。

第一次捕获故障后，后台线程输出 `reason=fault` 和最近最多 32 轮的
`EtherCAT timing history:`，随后冻结历史，避免断电后的连带报错覆盖现场。
`start_mono_us` 是循环开始的单调时钟时间，可结合周期编号关联记录。
首条通信故障本身也附带计时，因此即使后台采样发生竞争，仍能看到具体失败查询的
`elapsed_us`、`timeout_us` 及当前周期收发耗时。故障行中的 `timing_before_send`
和 `timing_before_latch` 是对应阶段的部分记录，尚未执行的阶段（包括最终超期统计）
为 0；完整周期统计以 history 为准。程序正常退出时也会输出未满 5 秒的窗口。

循环中仅采集数值并尝试写入固定大小的内存缓冲区；新增统计格式化和输出均在后台线程，
不在每个通信周期刷日志。

## 第四轴遥控位置

四个 EtherCAT 从站均使用 profile PDO；第 4 轴使用 PP 位置控制。上电保持实际启动位置，不自动回零、不自动移动到软件边界。前三轴的回零和末端控制保持原有行为。

button0 / button4 分别控制第 4 轴正向 / 反向移动，松手减速停止并保持位置。启动或重连后先松开两个按钮；两键同时按下停止并要求全部松开。button11 急停仍然有效。x/z/pitch 选择和 axis7 点动独立。

项目 `src/config/yiyou_ethercat.yaml` 设置 `yiyou_motor_4_speed_rpm: 12.0`，即减速器输出轴最高 12 RPM（72°/秒）；加减速度 `yiyou_motor_4_acceleration_rpm_s: 24.0`，理论上从 12 RPM 减至零约需 0.5 秒、18° 行程，实际受驱动器和负载影响。松手保持的是减速后的停止位置，不能瞬时刹停。两参数只在启动时读取，前三轴仍为 0.6 RPM、1 RPM/s。

软件目标范围为按原有编码器零点换算的累计输出角 **0°～1200°**（不是取模角度）。正常运行时目标脉冲限制在范围内，反馈到达边界后禁止继续向外；已在范围外时只允许按键向内逐步返回。每次目标基于当前反馈前方最多 0.5 秒的行程（12 RPM 时约 36°），卡住不会积累更远的目标。软件目标限制不能代替机械限位或保证实际位置完全不超调。

第四轴的累计圈数由主机保存到工程 `state/yiyou_motor4_position.yaml`，遥控程序与 `start_yiyou_jog.sh ... --slaves 4` 的后台共用该记录。驱动器断电后若把 1200° 报成 120°，主机按保存的运动区间恢复相差的三圈；目标下发时也换算回驱动器原始坐标。驱动器若仍报告 1200°，不会重复加圈。启动保持实际位置，不自动设零。

此恢复要求**断电期间第四轴没有机械运动**，并且所有第四轴运动均通过上述程序执行。记录绑定 EtherCAT 网口、站位、电机身份与编码器比例；每个目标触发前，后台线程先原子保存并同步其可达区间（含约 2° 余量、总宽度小于一圈）。松手会立即取消待发目标；反向或重新按键要等旧运动停稳。程序崩溃或硬断电不依赖退出保存。磁盘写入失败、记录缺失/损坏、身份或位置校验不通过都会拒绝运动；主程序按故障流程下电。

调试工具会区分可信累计角度与未恢复的原始角度。未恢复时禁止第四轴步进和回零，但保留显式 `Z` 设零入口：先停稳并失能、将旧记录标为无效，再执行设备零点保存，成功后写入新的零位记录。只有在确认机械臂处于所需零位时才按 `Z`。第四轴调试 `home` 和旧 `arm_yiyou_test` 的原始运动/设零入口已拒绝，避免绕过记录与限位。前三轴原有行为不变。

`yiyou_motor_4_position_memory_file` 可覆盖主程序记录的绝对路径；调试后台 `arm_yiyou_control --position-memory` 必须指定同一文件。不要删除或复制历史记录来绕过校验；换机、换比例或用其他软件移动过第四轴后，应在已知机械零位重新标定。

遥控通过 `/arm_motor4_jog` 每 50 ms 发布 `std_msgs/msg/Int8`，值为 -1、0 或 1；发送和接收节点可同时覆盖 `arm_position_topic`。断连、反馈失效、双键冲突均发送零。接收端 300 ms 未收到有效刷新则停止并要求先收到零再恢复；非法消息同样停止。控制器先处理超时，再推进 PP 握手。

停止/反向会取消正在准备、等待应答或已接受的旧目标；驱动器保留使能和 Halt，只有新目标完成写入、回读校验并触发时才释放 Halt。PP 应答超时、模式/状态错误、目标回读失败及反馈速度达到 60 RPM 时沿用故障锁存和共享电源断电处理。

旧 `arm_current_permille` 和 `yiyou_motor_4_current_permille` 非零值被拒绝，`/arm_motor4_current` 不再被订阅。此前 50% 是 CST 电流指令，**不是 PP 模式的力矩上限**；本改动没有写入新的驱动器限流/限矩参数。PP 的实际出力由驱动器位置环及已有驱动器限制决定，位置控制不能消除机械卡滞。

以上握手、限位及遥控异常行为有离线伪驱动和 ROS 测试覆盖；实际运动方向、减速距离、保持效果及机械卡滞原因仍需实机观察。
