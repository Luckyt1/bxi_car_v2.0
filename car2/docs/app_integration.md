# 现有 App 接入 car2

适用于同一块主板、同一台工控机：保留 `car2` 的 BXI/CAN/EtherCAT 驱动、机械参数、零偏和控制循环，在相邻 `app/bxi_rc_ros2` 网关增加 `car2` 后端。手机端继续使用已有 Wi-Fi/BLE 鉴权、控制权、安全过滤和 OTA 页面。

## 接口

| 接口 | 含义 |
| --- | --- |
| App `vx/vy/wz` | 归一化比例 `[-1,1]`，满杆分别为 `0.6 m/s`、`0.6 m/s`、`1 rad/s` |
| `/cmd_vel_car`，`geometry_msgs/Twist` | 网关转换后的车体速度，X 向前、Y 向左、yaw 逆时针；保留控制器 300 ms 断流停车 |
| `/car2/ready`，`std_msgs/Header` | 硬件初始化和校准完成后，每次成功控制周期发布；网关 300 ms 收不到即判离线 |
| `/car2/state_machine_info`，`std_msgs/String` | 每 100 ms 发布当前状态和动态动作清单；不伪造关节反馈 |
| `/car2/arm_command`，`std_msgs/Int8` | 网关将专用 `btn_10` 值转换成一次动作；发布端保留最新消息并设 100 ms 有效期 |

App 启动使用无手柄节点的 `chassis`；仅底盘模式使用 `chassis_only`。启动过程沿用本机配置的回零和校准行为。`app_interface_enabled:=true` 才启用上述 App 状态与机械臂接口，原手柄入口默认关闭该接口。导航速度的归一化比例与出口比例保持一致，输出不会回流到导航输入。

机械臂动作在 App 当前状态动作栏显示，不沿用 ELF3 的舞蹈或站高含义：

| `btn_10` / Int8 | 动作 |
| --- | --- |
| 101 / 102 | 末端 X 正向 / 负向 1 cm |
| 103 / 104 | 末端 Z 正向 / 负向 1 cm |
| 105 / 106 | 末端 pitch 正向 / 负向 1° |
| 107 / 108 | 第四轴正向 / 负向短点动，最多 100 ms 的指令窗口 |
| 109 | 取消机械臂目标、停止视觉跟踪，减速停止并保持 |

前三轴经过现有 IK、关节限位、姿态分支及视觉控制权检查；忙碌或不可达请求会拒绝并记录日志。第四轴沿用现有限位、PP 模式和位置记忆，不持续锁存按键。三轴配置不显示第四轴动作，仅底盘配置不显示机械臂动作。移动动作 101–108 的同一 100 ms 按钮脉冲只转换一次，防止一个点击执行多步。断链或安全门关闭时持续发送 109，确保控制循环卡顿恢复后仍能收到新的停臂请求；重复停止不重复操作硬件。

## 启停与升级

通过持久配置 `/etc/bxi/control_backend.env` 设置 `BXI_CONTROL_BACKEND=car2`；网关和 car2 必须继承同一 DDS/ROS domain。默认给回零和校准保留 900 秒启动等待，期间 App 的停止按钮可取消启动。Wi-Fi 状态提供 `start_timeout_sec`，BLE 使用 900 秒默认值；自定义更长等待时使用 Wi-Fi。停止的进程退出宽限为 15 秒；不会自动重启控制器。

OTA 把独立 `car2` 包替换到 `/opt/bxi/car2`，用它替代旧 RL Controller 的升级项。控制程序与 OTA 部署持有同一文件锁，运行时拒绝部署；标定、配置、第四轴位置记忆和日志留在包外。首次迁移、构建、制包及升级操作见 [car2_ota.md](car2_ota.md)，持久环境样例见 [car2-app.env](../deploy/car2-app.env)。缺少本机第四轴可信位置记忆时，应从原运行目录迁移，程序不会假定零位。

## 验证边界

离线检查覆盖单位转换、状态和按钮协议、失联、启停取消、配置迁移、锁互斥、制包校验和失败回退。编译或测试不启动主控硬件。真实机器仍需验证首次回零/校准、摇杆方向、机械臂动作、停机及升级后的重新启动；相同主板和电脑不能替代这些运动验证。
