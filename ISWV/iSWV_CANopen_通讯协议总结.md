# iSWV 立式舵轮 CANopen 通讯协议总结

> 来源：`iSWV立式舵轮使用手册20260311.pdf`，手册 V1.0，2026-03-11。  
> 适用对象：型号尾码为 **A** 的 iSWV-AA（RS485 + CANopen）机型；尾码为 **E** 的机型使用 EtherCAT，不属于本文范围。  
> 本文目标：把手册中分散在接线、工作模式、对象字典和 CANopen 章节里的内容，整理成一份可直接用于主站程序设计和现场调试的说明。

## 1. 先建立整体概念

iSWV-AA 不是自定义裸 CAN 协议，而是：

```text
经典 CAN 物理层
  └─ CANopen（NMT / SDO / PDO / SYNC / Heartbeat / EMCY）
       └─ CiA 402 / DS402 伺服控制（控制字、状态字、速度/位置/力矩/回零）
```

真正让电机运行，需要同时处理两层状态：

1. **CANopen NMT 状态**：节点上电后进入 Pre-operational；PDO 通讯前应发送 NMT Start，使节点进入 Operational。
2. **CiA 402 驱动状态**：通过 `6040:00` 控制字执行 `0x0006 → 0x0007 → 0x000F`，使驱动器进入 Operation enabled。

这两个状态机不要混为一谈。NMT Operational 只说明 CANopen 节点允许 PDO 工作，不等于电机已经使能。

舵轮内有两个独立执行轴：

- 行走轴：通常使用速度模式；
- 转向轴：通常使用位置、回零或插补模式。

手册图 3-5 显示两轴各自有 CAN 接口，可按两个 CANopen 从站理解。若接到同一总线，必须给它们配置不同的 Node-ID。每个驱动器出厂 Node-ID 默认都是 1，因此建议先逐个单独接线改地址，再把两个节点并到总线上。

## 2. 物理层和接线

### 2.1 基本参数

- 最大波特率：1 Mbit/s；
- 默认波特率：500 kbit/s；
- 默认 Node-ID：1；
- Node-ID 范围：1～127；
- 默认使用 CANopen 2.0A 的 11 位 CAN-ID；手册称设备也支持 CAN 2.0B/29 位扩展标识符和自定义 PDO COB-ID，但常规项目优先使用标准 11 位连接集。

### 2.2 接线原则

- `CAN_H` 接所有节点的 `CAN_H`，`CAN_L` 接所有节点的 `CAN_L`；
- 总线采用干线串接，不要接成星形；
- 只在总线两端各接一个 120 Ω 终端电阻；
- 使用屏蔽双绞线，长距离或高波特率时接好信号地/屏蔽地；
- CAN 空闲时 `CAN_H`、`CAN_L` 都约为 2.5 V；显性位时典型值约为 3.5 V 和 1.5 V。

手册给出的理论距离如下，实际工程应根据线材、支线长度、节点数量和电磁环境留余量：

| 波特率 | 理论最大距离 |
|---:|---:|
| 1 Mbit/s | 25 m |
| 800 kbit/s | 50 m |
| 500 kbit/s | 100 m |
| 250 kbit/s | 250 m |
| 125 kbit/s | 500 m |
| 50 kbit/s | 600 m |
| 25 kbit/s | 800 m |
| 10 kbit/s | 1000 m |

注意：波特率设置对象中没有列出 800 kbit/s 和 25 kbit/s 的编码。要使用这两个速率，应先以设备 EDS 和实机验证结果为准。

### 2.3 iSWV-AA 接口引脚

行走轴反馈线缆：

| 引脚 | 信号 |
|---:|---|
| 11、12 | CAN_L |
| 13、14 | CAN_H |
| 6 | GNDC |
| 15 | 120-R1 |
| 7 | 120-R2 |

短接 `120-R1` 和 `120-R2` 即启用内置 120 Ω 终端电阻。

转向轴独立 CAN 接口：

| 引脚 | 信号 |
|---:|---|
| 1、3 | CAN_L |
| 2、4 | CAN_H |

转向轴终端电阻接口为：2 脚 `120-R2`、4 脚 `120-R1`，两者短接后启用内置终端电阻。

## 3. 手册中的对象地址怎么读

手册经常把一个对象写成 8 位十六进制数：

```text
60400010
└6040┘└00┘└10┘
 Index  Sub  位长度
```

因此：

- `60400010` = Index `0x6040`、Subindex `0x00`、长度 `0x10` bit，即 2 字节；
- `60600008` = `6060:00`，1 字节；
- `607A0020` = `607A:00`，4 字节。

本文统一写作 `Index:Subindex`，例如 `6040:00`。末尾的位长度只是手册的辅助标记，不是 Index 的一部分，也不是 CAN 报文 ID。

多字节对象全部按 **小端序** 传输，即低字节在前。`Integer8/16/32` 为有符号二进制补码，`Unsigned8/16/32` 为无符号数。

## 4. CANopen COB-ID 总表

下表中的 `N` 表示 Node-ID：

| 功能 | COB-ID | 方向（相对驱动器） |
|---|---:|---|
| NMT 管理 | `0x000` | 主站 → 从站 |
| SYNC | `0x080` | 主站 → 全网 |
| TIME | `0x100` | 主站 → 全网 |
| EMCY | `0x080 + N` | 从站 → 主站 |
| TPDO1 | `0x180 + N` | 从站 → 主站 |
| RPDO1 | `0x200 + N` | 主站 → 从站 |
| TPDO2 | `0x280 + N` | 从站 → 主站 |
| RPDO2 | `0x300 + N` | 主站 → 从站 |
| TPDO3 | `0x380 + N` | 从站 → 主站 |
| RPDO3 | `0x400 + N` | 主站 → 从站 |
| TPDO4 | `0x480 + N` | 从站 → 主站 |
| RPDO4 | `0x500 + N` | 主站 → 从站 |
| SDO 应答（Server → Client） | `0x580 + N` | 从站 → 主站 |
| SDO 请求（Client → Server） | `0x600 + N` | 主站 → 从站 |
| Heartbeat / Node Guard | `0x700 + N` | 通常从站 → 主站 |

CAN 仲裁中，数值越小优先级越高。

## 5. NMT：节点启动和网络状态

节点初始化完成后会：

1. 发送 Boot-up：`COB-ID = 0x700 + N`，数据 `00`；
2. 自动进入 Pre-operational；
3. 此时可以用 SDO 配置参数和 PDO；
4. 主站发送 NMT Start 后，节点进入 Operational，PDO 才正常工作。

NMT 帧固定使用 CAN-ID `0x000`，数据为两个字节：

```text
Byte0 = Command Specifier
Byte1 = Node-ID，0 表示广播给所有从站
```

| Byte0 | 含义 |
|---:|---|
| `01` | Start Remote Node，进入 Operational |
| `02` | Stop Remote Node |
| `80` | 进入 Pre-operational |
| `81` | Reset Node |
| `82` | Reset Communication |

例如启动 1 号节点：

```text
CAN-ID  DLC  DATA
000     2    01 01
```

NMT 命令没有应答。主站应通过 Heartbeat、PDO 或 SDO 读取状态来确认后续结果。

## 6. SDO：参数读写

SDO 是有请求、有应答的低优先级参数通道，适合初始化和配置，不适合高频实时控制。

### 6.1 报文格式

SDO 固定 DLC=8：

| 字节 | 内容 |
|---:|---|
| 0 | SDO 命令字 |
| 1 | Index 低字节 |
| 2 | Index 高字节 |
| 3 | Subindex |
| 4～7 | 对象数据，小端序；不足部分填 0 |

主站请求使用 `0x600 + N`，从站应答使用 `0x580 + N`。

### 6.2 常用命令字

| 操作 | 请求 Byte0 | 正常应答 Byte0 |
|---|---:|---:|
| 读对象 | `40` | 1 字节 `4F`；2 字节 `4B`；4 字节 `43` |
| 写 1 字节 | `2F` | `60` |
| 写 2 字节 | `2B` | `60` |
| 写 4 字节 | `23` | `60` |
| 访问失败 | — | `80`，Byte4～7 为 32 位 Abort Code |

### 6.3 例子：1 号节点写目标位置 100000 inc

`100000 = 0x000186A0`，写入 `607A:00`：

```text
主站 → 从站
CAN-ID  DATA
601     23 7A 60 00 A0 86 01 00

从站 → 主站
CAN-ID  DATA
581     60 7A 60 00 00 00 00 00
```

SDO 下载应答中的 Byte4～7 不应作为回读值使用；如果要确认数值，应再发一次 SDO 读取。

### 6.4 例子：读取状态字

```text
主站 → 从站
601     40 41 60 00 00 00 00 00

从站 → 主站，例如状态字为 0x0037
581     4B 41 60 00 37 00 00 00
```

### 6.5 SDO Abort Code

| Abort Code | 含义 |
|---:|---|
| `0x05040001` | 非法/未知命令字 |
| `0x06010001` | 试图读取只写对象 |
| `0x06010002` | 试图写入只读对象 |
| `0x06020000` | 对象不存在 |
| `0x06040041` | 对象不支持 PDO 映射 |
| `0x06060000` | 驱动器故障状态导致访问失败 |
| `0x06070010` | 数据类型或长度不匹配 |
| `0x06070012` | 数据长度太大 |
| `0x06070013` | 数据长度太短 |
| `0x06090011` | 子索引不存在 |
| `0x06090030` | 数值超出范围 |
| `0x06090031` | 数值过大 |
| `0x06090032` | 数值过小 |
| `0x08000022` | 当前设备状态不允许传输/保存 |

Abort Code 也按小端序放在 Byte4～7。例如字节 `01 00 01 06` 表示 `0x06010001`。

## 7. PDO：实时过程数据

PDO 每帧最多 8 字节，不带 Index/Subindex，也没有应答。双方必须提前约定相同的映射和字节顺序。

- TPDO：驱动器发送，主站接收；
- RPDO：主站发送，驱动器接收；
- 一个 PDO 中所有映射对象的长度总和不能超过 64 bit；
- 每个对象仍按小端序排列。

手册给出的典型 TPDO1 映射是：

```text
6063:00 实际位置  32 bit
6041:00 状态字    16 bit
总计              6 byte
```

若映射顺序确实按上面配置，则 TPDO 数据布局为：

```text
Byte0..3 = 实际位置（Int32，小端）
Byte4..5 = 状态字（UInt16，小端）
```

这只是手册中的配置示例，不应当成所有设备的出厂默认映射。支持 EDS 的主站应导入厂家 EDS，并由主站在上电时通过 SDO 配置 PDO。标准 CANopen 通常使用 `1400～1403/1600～1603` 配置 RPDO、`1800～1803/1A00～1A03` 配置 TPDO，但手册没有完整列出这些对象，最终以 EDS 和实机对象字典为准。

### 7.1 传输类型

| 类型 | 行为 |
|---:|---|
| `0` | 非周期同步/事件触发，在 SYNC 关系下发送 |
| `1～240` | 周期同步；每收到 n 个 SYNC 触发一次 |
| `254/255` | 异步；数据变化可触发 TPDO |

SYNC 默认 CAN-ID 为 `0x080`、DLC=0。手册称设备最高支持 1 kHz 的 SYNC。

RPDO 默认传输类型为 254，收到后立即生效。异步 TPDO 可配置：

- 禁止时间：限制相邻两帧 TPDO 的最小间隔；手册界面按 ms 描述；
- 事件时间：即使数据不变，也按设定周期上传，单位 ms。

注意：CiA 301 标准对象的 Inhibit Time 原始单位通常是 100 μs，而本手册明确把界面/参数解释为 1 ms。直接写对象时必须以 EDS 的单位定义和抓包验证为准。

## 8. Heartbeat、Node Guard 和通讯中断

### 8.1 Heartbeat

从站 Heartbeat：

```text
CAN-ID = 0x700 + Node-ID
Byte0  = NMT 状态
```

| 状态值 | 含义 |
|---:|---|
| `00` | Boot-up |
| `04` | Stopped |
| `05` | Operational |
| `7F` | Pre-operational |

`1017:00` 为 Heartbeat Producer Time。从站启动后的第一帧 Heartbeat 是 Boot-up `00`。

### 8.2 Node Guard

主站周期发送 `0x700 + N` 的 RTR 远程帧，从站返回 1 字节：

```text
bit7    = Toggle，每次应答在 0/1 间翻转
bit6..0 = NMT 状态
```

相关对象：

- `100C:00`：Guard Time，默认 1000 ms；
- `100D:00`：Life Time Factor，默认 3；
- 超时时间约为 `Guard Time × Life Time Factor`。

Heartbeat 与 Node Guard 只能选一种监督方式，不能同时使用。

### 8.3 驱动器在断线时是否停机

`6007:00` 为 CAN 通讯中断模式：

- `0`：不处理，默认值；
- `1`：通讯超时后驱动器报错停机。

也就是说，**出厂默认并不会因为 CAN 断线自动报错停机**。移动机器人项目应明确配置通信监督方式和 `6007:00=1`，并在整车控制器中另设硬件急停/失联安全策略，不能只依赖 CAN 软件看门狗。

手册同时描述了“由驱动器监视主站 Heartbeat”的用法，但没有完整列出消费者对象和配置流程；这部分应以 EDS 为准并做断线实测。手册还说明 Heartbeat/Node Guard 参数通常由主站每次上电重新配置，默认不保证掉电保存。

## 9. EMCY 应急报文

驱动器发生严重故障时主动发送：

```text
CAN-ID = 0x080 + Node-ID
DLC    = 8
```

按手册表 9-23：

| 字节 | 内容 |
|---:|---|
| 0～1 | `603F:00` 应急错误代码，UInt16，小端 |
| 2 | `1001:00` 错误寄存器 |
| 3 | 手册未说明，按保留字节处理 |
| 4～5 | `2601:00` 错误状态 |
| 6～7 | `2602:00` 错误状态 2 |

与 CAN 直接相关的错误码包括：

- `0x8100`：总线通讯错误；
- `0x81FF`：总线通讯超时。

`1001:00` 错误寄存器位定义：bit0 一般错误、bit1 电流、bit2 电压、bit3 温度、bit4 通讯、bit5 设备配置、bit6 编码器。

## 10. CiA 402 驱动状态机

### 10.1 最小使能流程

建议不要只写一次 `0x000F`，而是按状态机逐步执行并检查状态字：

| 步骤 | 写 `6040:00` | 期望状态 | 判断方式 |
|---:|---:|---|---|
| 1 | `0x0006` | Ready to switch on | `(6041 & 0x006F) == 0x0021`；手册典型值 `0x0031` |
| 2 | `0x0007` | Switched on | `(6041 & 0x006F) == 0x0023`；手册典型值 `0x0033` |
| 3 | `0x000F` | Operation enabled | `(6041 & 0x006F) == 0x0027`；手册典型值 `0x0037` |

不要直接用完整状态字等值判断，因为警告、限位、目标到达、回零完成等高位会动态变化。

常用控制字：

| 控制字 | 含义 |
|---:|---|
| `0x0006` | Shutdown/松轴，进入 Ready to switch on |
| `0x0007` | Switch on |
| `0x000F` | Enable operation/锁轴 |
| `0x000B` | 快速停止（手册常用写法） |
| `0x0086` | 故障复位，bit7 上升沿有效；复位后应清掉 bit7 |

控制字重要位：

| 位 | 含义 |
|---:|---|
| bit0 | Switch on |
| bit1 | Enable voltage |
| bit2 | Quick stop，0 表示执行快速停止 |
| bit3 | Enable operation |
| bit4 | 新位置指令/回零触发；插补模式下为插补使能 |
| bit5 | 位置参数立即更新 |
| bit6 | 位置模式下 0=绝对，1=相对 |
| bit7 | Fault reset，上升沿有效 |
| bit8 | Halt，除力矩模式外适用 |
| bit12 | 位置模式下，目标变化时立即更新绝对轨迹 |

### 10.2 状态字 `6041:00`

| 位 | 含义 |
|---:|---|
| bit0 | Ready to switch on |
| bit1 | Switched on |
| bit2 | Operation enabled |
| bit3 | Fault |
| bit4 | Voltage enabled |
| bit5 | Quick stop |
| bit6 | Switch on disabled |
| bit7 | Warning |
| bit9 | Remote，1=通讯控制 |
| bit10 | Target reached；位置到/速度到/零速到 |
| bit11 | 正/负限位激活 |
| bit12 | 位置模式 Set-point Ack；速度模式为零速；回零模式为回零错误 |
| bit13 | 位置跟随误差 |
| bit14 | 已找到电机励磁 |
| bit15 | 回零完成/参考点已找到 |

若 bit3=1，先读取 `2601:00` 和 `2602:00` 查明故障原因，排除原因后再给 `0x0086` 复位。不要在原因未排除时循环强制复位。

## 11. 工作模式

`6060:00` 是有符号 Int8：

| 数值 | 模式 | 常见用途 |
|---:|---|---|
| `-4` | 脉冲模式 | 外部脉冲控制 |
| `-3` | 立即速度模式 | 目标速度立即作用，不走梯形加减速 |
| `1` | 位置模式 | 转向定位 |
| `3` | 带加减速的速度模式 | 行走控制 |
| `4` | 力矩模式 | 转矩/推力控制 |
| `6` | 回零模式 | 建立转向参考零点 |
| `7` | CANopen 插补模式 | 主站周期规划、多轴同步 |

写入 `-3` 时，线上 1 字节补码为 `FD`；写入 `-4` 为 `FC`。

### 11.1 速度模式

相关对象：

| 对象 | 类型 | 含义 |
|---|---|---|
| `6060:00` | Int8 | `3` 或 `-3` |
| `60FF:00` | Int32 | 目标速度 |
| `6083:00` | UInt32 | 梯形加速度，模式 3 生效 |
| `6084:00` | UInt32 | 梯形减速度，模式 3 生效 |
| `606C:00` | Int32 | 实际速度 |
| `607E:00` | UInt8 | 方向：0 逆时针为正，1 顺时针为正；使能状态不能改 |

建议顺序：松轴 → 设置方向和模式 → 设置加减速度 → 设置目标速度 → 执行 402 使能流程。运行中通过 RPDO 或 SDO 更新 `60FF:00`。

### 11.2 位置模式

| 对象 | 类型 | 含义 |
|---|---|---|
| `6060:00` | Int8 | 写 `1` |
| `607A:00` | Int32 | 目标位置，单位 inc |
| `6081:00` | UInt32 | 梯形速度 |
| `6083:00` | UInt32 | 梯形加速度 |
| `6084:00` | UInt32 | 梯形减速度 |
| `6063:00` | Int32 | 实际位置 |

控制字触发方式：

- 绝对定位：`0x002F → 0x003F`；
- 相对定位：`0x004F → 0x005F`；
- 目标位置变化后立即绝对定位：保持/写入 `0x103F`。

bit4 的 0→1 上升沿用于激活一条新位置指令。到位后 `6041.bit10=1`。

### 11.3 回零模式

| 对象 | 类型 | 含义 |
|---|---|---|
| `6060:00` | Int8 | 写 `6` |
| `6098:00` | Int8 | 回零方法 |
| `6099:01` | UInt32 | 寻找开关/转折信号速度 |
| `6099:02` | UInt32 | 寻找原点信号速度 |
| `609A:00` | UInt32 | 回零加速度 |
| `607C:00` | Int32 | 原点偏移 |

常见回零方法：17 负限位、18 正限位、19～22 外接原点开关、33/34 下一个编码器 Z 相、35 当前点为原点、-17/-18 机械末端回零。

先完成普通使能，再用 `0x000F → 0x001F` 触发回零。`6041.bit15=1` 表示回零完成，`6041.bit12=1` 在回零模式下表示回零错误。

### 11.4 插补模式

插补模式由主站周期更新 `607A:00`，配合 SYNC 进行单轴轮廓或多轴同步：

| 对象 | 含义 |
|---|---|
| `6060:00 = 7` | 插补模式 |
| `3011:01` | 同步周期：0=1 ms，1=2 ms，2=4 ms，3=8 ms |
| `3011:02` | 同步时钟模式；说明文字要求插补时置 1 |
| `3011:04` | 同步丢失计数，持续增长说明干扰或周期不匹配 |
| `6040:00 = 0x001F` | 使能插补 |

主站的 SYNC 周期必须与 `3011:01` 一致。推荐把目标位置映射到 RPDO，把实际位置和状态字映射到 TPDO。

## 13. 速度、加速度和位置的原始值换算

手册表格虽然把 `60FF`、`6081` 等单位写成 rpm，但 SDO 示例证明 CAN 报文里传输的是换算后的内部整数，不是直接填 rpm 数字。

设编码器每转分辨率为 `R`：

### 13.1 速度

```text
raw_speed = rpm × 512 × R / 1875
rpm       = raw_speed × 1875 / (512 × R)
```

适用于手册列出的目标速度、梯形速度和实际速度等速度对象。结果按对象类型取整，负速度使用 Int32 二进制补码。

手册示例使用 `R = 65536`：

- `200 rpm → 3579139 → 0x00369D03 → 03 9D 36 00`；
- `-100 rpm → -1789570 → 0xFFE4B17E → 7E B1 E4 FF`。

### 13.2 加速度/减速度

```text
raw_acc = (rps/s) × 65536 × R / 4000000
rps/s   = raw_acc × 4000000 / (65536 × R)
```

当 `R = 65536` 时：

```text
100 rps/s → 107374 → 0x0001A36E → 6E A3 01 00
```

### 13.3 位置

`607A` 和 `6063` 的单位为电机侧编码器增量 inc。换算转向角度或轮子行程时，还要结合：

- 编码器每转分辨率；
- 减速比；
- 轮径；
- 安装方向和机械零点。

手册没有在 CAN 章节给出可直接套用的整机角度/米制换算常数，因此不要把 1 inc 直接理解成 1° 或 1 mm。建议通过规格参数和实机转一圈计数校准后，在整车软件中统一转换。

### 13.4 电流/力矩的注意点

手册给出的电流换算为：

```text
1 Arms 对应的 raw = 2048 / (Ipeak / 1.414)
```

其中 `Ipeak` 是驱动器峰值电流。但手册同时把 `6071:00` 描述为“额定力矩百分比”，又在换算备注里把它列入电流对象，前后不一致。力矩模式上线前应以 EDS、KS3 显示值和小电流实测为准，不要直接满量程下发。

## 14. 一个可落地的主站启动流程

```text
1. 分别给行走轴、转向轴配置唯一 Node-ID；设置统一波特率，保存并重启。
2. 检查 CAN_H/CAN_L、屏蔽地和总线两端 120 Ω 终端。
3. 启动主站，等待每个节点的 Boot-up：0x700+N，数据 00。
4. 节点处于 Pre-operational，用 SDO：
   - 检查身份/关键参数；
   - 配置 Heartbeat 或 Node Guard；
   - 写 6007:00=1；
   - 配置 RPDO/TPDO 映射、传输类型和周期。
5. 发送 NMT Start：000#01NN，使节点进入 Operational。
6. 设置 6060 工作模式及模式参数。
7. 按 6040 = 0006 → 0007 → 000F 使能，并逐步校验 6041。
8. 运行中用 RPDO 下发目标，用 TPDO接收实际位置/速度/状态字。
9. 持续监控 Heartbeat、EMCY、6041、2601 和 2602。
10. 正常停机先把目标速度降为 0，再按需要写 0006；急停使用硬件安全链路并配合快速停止。
```

## 15. Node-ID=1 的原始 CAN 报文速查

下面只用于联调，`#` 后为十六进制数据：

```text
# NMT 启动 1 号节点
000#0101

# 写工作模式 3（带加减速速度模式）
601#2F60600003000000

# R=65536 时，写目标速度 -100 rpm
601#23FF60007EB1E4FF

# R=65536 时，写加速度 100 rps/s
601#238360006EA30100

# 写减速度 100 rps/s
601#238460006EA30100

# CiA 402：Shutdown → Switch on → Enable operation
601#2B40600006000000
601#2B40600007000000
601#2B4060000F000000

# 读状态字
601#4041600000000000

# 写目标位置 100000 inc
601#237A6000A0860100

# 故障复位脉冲
601#2B40600086000000
601#2B40600006000000
```

每条 SDO 写请求都要等待 `581` 上的 `0x60` 正常应答后再发下一条；若收到 `0x80`，解析 Abort Code，不能继续盲发。

## 16. 手册中需要特别防范的歧义/笔误

1. **SDO 应答 COB-ID**：表 9-5 正确写为 `0x580 + Node-ID`，但后面的写对象示例把从站应答写成了 `0x601`。Node-ID=1 时正确应答 ID 应为 `0x581`。
2. **SDO 写应答数据区**：手册示例把原请求数据原样回显；标准 SDO 下载成功只要求命令字 `0x60` 和相同 Index/Subindex，Byte4～7 应忽略。
3. **工程单位与线上原始值**：表格写 rpm/rps/s，但报文示例使用内部换算整数。实现时必须按第 13 节公式处理。
4. **最大速度对象**：第 5 章使用标准对象 `607F:00`，第 7 章又列出 `6080:00`，且数据长度描述互有冲突。应以本机 EDS 为准。
5. **插补同步时钟**：表 9-27 的说明文字要求插补模式把 `3011:02` 设为 1，但“设置值”栏又显示 0。应按说明文字设 1，并通过 `3011:04` 和实机运动验证。
6. **EMCY Byte3**：表 9-23 跳过了 Byte3。解析时先按保留字节处理，并用实机故障抓包确认厂家字段布局。
7. **通讯保护命名**：手册把主站/从站 Heartbeat 的称呼写得容易混淆。实现时以“谁生产 Heartbeat、谁消费 Heartbeat”来区分，不要只看章节小标题。
8. **800 kbit/s 和 25 kbit/s**：距离表中存在，但波特率编码表未提供设置值，不能据此认定设备可配置这两个速率。

## 17. 实施建议

- 优先取得与固件版本匹配的厂家 EDS，PDO 映射、可写属性、默认值都以 EDS 和实机为最终依据；
- 上位机 KS3 使用 CAN 通讯时，不要同时让 PLC/Linux 主站向同一驱动器发送 SDO/PDO，手册明确提示这会导致 KS3 通讯异常；
- 首次运动时架空轮组、限制速度/电流，并准备硬件急停；
- 抓包时至少记录时间戳、CAN-ID、DLC、数据、NMT 状态、`6041`、`2601/2602`，这样才能区分总线问题、CANopen 状态问题和伺服状态问题；
- 如果要写正式驱动程序，建议把 SDO、NMT、PDO、CiA 402、单位换算和整车安全监控拆成独立模块，不要把所有状态塞进一个收发循环。
